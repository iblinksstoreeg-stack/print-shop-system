# نظام إدارة أوردرات المطبعة — نسخة مستقلة

نظام يشتغل **على جهازك** دلوقتي، وبنفس الملفات تقدر ترفعه **على أي استضافة بدومين** من غير تعديل في الكود.
مفيش مكتبات خارجية ولا قاعدة بيانات تتركّب. بس **Node.js**.

## 1) التشغيل على جهازك (Windows)

1. نزّل وركّب **Node.js** (النسخة LTS) من https://nodejs.org (ضغطة Next كام مرة).
2. فك ضغط الملف `print-shop-system.zip` في أي مكان (مثلًا `C:\PrintShop`).
3. اضغط **دبل كليك** على `start.bat`. هيفتح المتصفح على `http://localhost:3000` لوحده.
4. ادخل بـ: الاسم **المالك** والرقم السري **123456**.
5. **غيّر رقمك السري فورًا:** اضغط على اسمك فوق ← «تغيير الرقم السري».
6. من **👥 الموظفين** أضف موظفينك (اسم + رقم سري + دور)، ومن **⚙️ الإعدادات** أضف صفحات الفيس بوك وشعاراتها.

> سيب نافذة `start.bat` السوداء مفتوحة طول ما بتستخدم النظام. إقفالها بيوقف النظام.

### فتح النظام من أجهزة تانية في نفس الشبكة (موبايلات الموظفين مثلًا)
- لما يشتغل، النافذة السوداء بتكتب سطر مثل `http://192.168.1.20:3000`. افتحه من أي جهاز على نفس الواي فاي.
- لو ما اتفتحش: وافق على رسالة **Windows Firewall** (Allow access) وقت أول تشغيل.
- الجهاز اللي عليه النظام لازم يفضل شغّال ومفتوح عليه `start.bat`.

## 2) مكان البيانات والنسخ الاحتياطي
كل حاجة في مجلد **`data`** جنب الملفات:
- `data/db.json` ← الأوردرات والمشتريات والموظفين والإعدادات
- `data/files/` ← الملفات المرفوعة (بروفات وغيره)
- `data/backups/` ← نسخة احتياطية يومية تلقائية من `db.json` (آخر 30 يوم)

**للنسخ الاحتياطي الكامل:** انسخ مجلد `data` كله على فلاشة أو درايف كل فترة.
**لنقل النظام لجهاز أو استضافة تانية:** انقل مجلد `data` كما هو.

## 3) الإعدادات (ملف `.env`)
أول تشغيل بيعمل ملف `.env` تلقائيًا من `.env.example`. أهم الإعدادات:

| الإعداد | معناه |
|---|---|
| `PORT` | المنفذ (افتراضي 3000) |
| `HOST` | `0.0.0.0` للشبكة، أو `127.0.0.1` لو خلف Nginx |
| `DATA_DIR` | مسار مجلد البيانات (على الاستضافة اجعله مسارًا ثابتًا) |
| `MAX_UPLOAD_MB` | أقصى حجم للملف المرفوع (افتراضي 50) |
| `OWNER_NAME` / `OWNER_PIN` | حساب المالك، بيتنشأ **أول مرة فقط** |
| `TRUST_PROXY` / `COOKIE_SECURE` | فعّلهم (1) خلف وسيط HTTPS |

لو عدّلت `.env` بالمفكرة: احفظه بترميز **UTF-8**.

## 3-ب) المخزن والخامات (جديد)
- **تبويب 📦 المخزن**: يشوفه المالك والمدير والسيلز. المالك بس هو اللي يضيف توريدات ويشوف التكلفة والقيمة.
- **توريد مشتريات للمخزن** (المالك): تكتب الأصناف وكمياتها وسعر الوحدة. لو الصنف موجود بيزيد رصيده وبيتحسب **متوسط التكلفة**، ولو جديد بيتضاف. وبيتسجل تلقائيًا في المشتريات (بعلامة «توريد مخزن») وفي المستحق للمورد لو دفعت جزء.
- **عند إنشاء أوردر جديد**: قسم «الخامات المستخدمة» لكل خامة تختار:
  - **سحب من المخزن**: بيخصم الكمية من المتاح بتكلفة الصنف وقت السحب (ولو الكمية مش كفاية بيرفض).
  - **مشتريات خارجية**: تكتب الوصف والكمية وتكلفتها (اختياري). لو كتبت التكلفة بتتسجل في المشتريات مربوطة بالأوردر.
- من صفحة أي أوردر: **+ إضافة خامة** و**إرجاع للمخزن** لأي خامة سُحبت (قبل التسليم).
- **الأرباح**: الخامات المسحوبة بتدخل في تكلفة الأوردر المسلَّم، وتوريد المخزن نفسه **مش مصروف** وقت الشراء (هو أصل بيتحسب تكلفة وقت السحب)، وفي الإحصائيات «قيمة المخزون الحالية».
- **المصمم ومسؤول التشغيل** ما بيشوفوش المخزن ولا الخامات ولا التكاليف، والسيرفر هو اللي بيحجبها. وحتى السيلز والمدير ما بيشوفوش تكلفة الأصناف (المالك فقط).
- **تسوية الكمية (جرد)**: من صفحة الصنف (للمالك) لتصحيح الرصيد مع تسجيل السبب في «سجل حركات المخزن».
- **حذف توريد** غلط: ممكن لو ما اتسحبش جزء منه (بيخصم كمياته من المخزن).

## 4) الرفع على استضافة بدومين

### أهم 3 شروط لأي استضافة
1. تدعم **Node.js** (نسخة 18 أو أحدث). استضافة PHP العادية الرخيصة **مش** هتنفع.
2. فيها **تخزين دائم** للمجلد `data` (مش بيتمسح مع كل إعادة تشغيل).
3. **HTTPS** مفعّل على الدومين. ده إجباري لأن الأرقام السرية بتتبعت وقت الدخول.

### أ) سيرفر VPS (Ubuntu) — الأكثر ثباتًا
```bash
# 1) ركّب Node و Nginx
sudo apt update && sudo apt install -y nginx
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - && sudo apt install -y nodejs

# 2) ارفع مجلد النظام (مثلًا إلى /opt/printshop) ثم:
cd /opt/printshop
cp .env.example .env && nano .env      # ضع OWNER_PIN قويًا + HOST=127.0.0.1 + TRUST_PROXY=1 + COOKIE_SECURE=1

# 3) شغّله دائمًا بـ pm2
sudo npm i -g pm2
pm2 start server.js --name printshop && pm2 save && pm2 startup

# 4) Nginx: انسخ nginx.conf.example إلى /etc/nginx/sites-available/printshop وعدّل الدومين، ثم:
sudo ln -s /etc/nginx/sites-available/printshop /etc/nginx/sites-enabled/ && sudo nginx -t && sudo systemctl reload nginx
sudo apt install -y certbot python3-certbot-nginx && sudo certbot --nginx -d yourdomain.com
```

### ب) cPanel (لو الاستضافة فيها «Setup Node.js App»)
1. ارفع الملفات (server.js، package.json، مجلد public) إلى مجلد خارج `public_html`، مثلًا `printshop`.
2. من **Setup Node.js App** أنشئ تطبيقًا: نسخة Node 18+، Application root = `printshop`، Startup file = `server.js`.
3. أضف متغيرات البيئة: `OWNER_PIN` (قوي) و`DATA_DIR=/home/USERNAME/printshop-data` و`COOKIE_SECURE=1`.
4. اضغط **Restart**. فعّل شهادة SSL للدومين من **SSL/TLS Status**.

### ج) Docker
```bash
docker build -t printshop .
docker run -d --name printshop -p 3000:3000 -v printshop-data:/data \
  -e OWNER_PIN=رقم-قوي -e COOKIE_SECURE=1 -e TRUST_PROXY=1 --restart unless-stopped printshop
```
(ضع أمامه Nginx أو Caddy أو Cloudflare للـ HTTPS.)

### د) منصات الاستضافة السحابية (Render / Railway / Fly.io)
تنفع بشرط تضيف **Volume (تخزين دائم)** وتربطه على مسار، وتضبط `DATA_DIR` على نفس المسار. من غير Volume البيانات هتضيع مع كل نشر جديد.

## 5) نقل بياناتك من الجهاز للاستضافة
1. اقفل النظام المحلي.
2. انسخ مجلد `data` من جهازك إلى مكان `DATA_DIR` في الاستضافة.
3. شغّل النظام هناك. هتلاقي كل الأوردرات والموظفين والملفات زي ما هي.

## 6) الأمان
- الأرقام السرية متخزنة **مشفّرة (scrypt)** ومش مقروءة حتى لو اتفتح ملف البيانات.
- 5 محاولات دخول غلط بتقفل الاسم 5 دقايق.
- الأسعار والعرابين وتليفونات العملاء **بتتحذف من السيرفر** قبل ما توصل للمصمم ومسؤول التشغيل.
- المشتريات والأرباح وإدارة الموظفين للمالك فقط، ومفروضة من السيرفر.
- الملفات المرفوعة بتتفتح للموظفين المسجّلين فقط، والمصمم بيشوف ملفات الأوردرات اللي في مرحلته بس.
- على الإنترنت: لازم **HTTPS** + رقم سري قوي للمالك + خد نسخة من `data` بانتظام.

## 7) محتويات المجلد
| الملف | وظيفته |
|---|---|
| `server.js` | الخادم (الدخول، الصلاحيات، حفظ البيانات، الملفات) |
| `public/index.html` | واجهة البرنامج |
| `package.json` | بيانات المشروع (مفيش مكتبات) |
| `.env.example` | نموذج الإعدادات |
| `start.bat` / `start.sh` | تشغيل سريع (ويندوز / لينكس وماك) |
| `Dockerfile`, `nginx.conf.example` | للاستضافة |
